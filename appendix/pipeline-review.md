## ROI

Counted: engineer time saved on triage, minus API cost and upkeep. Not counted: the value of the fixes themselves, which is shown separately below because it depends on engineering acting on the backlog.

| Scenario | Triage hours saved / year | Value of time saved | API cost / year | Upkeep / year | Net / year | ROI |
|---|---:|---:|---:|---:|---:|---:|
| One robot, quiet | 73 | $6,570 | $12.94 | $4,320 | $2,237 | 0.5× |
| One robot, busy | 365 | $32,850 | $64.72 | $4,320 | $28,465 | 6.5× |
| Robot fleet | 1,460 | $131,400 | $259 | $4,320 | $126,821 | 27.7× |

ROI = (value of time saved − API cost − upkeep) ÷ (API cost + upkeep). At these volumes the API bill is small next to upkeep, so the case rests on report volume and on how long manual triage really takes. Measure the manual time for a few weeks before relying on these numbers.

**What the current backlog points at** (from the agent's own impact estimates, if every issue were fixed):

- about 18 false-alarm callouts a month avoided, roughly $51,840 a year in on-call overtime at 2 h × $120/h;
- about 171 missed or unusable readings a week recovered, about 8,892 a year.

## Ways to cut the API cost

- **Lower effort for classification.** Classification is a short, well-specified task; run it at `low` effort (`SPOT_AGENT_EFFORT=low`) and re-check accuracy with `eval.py`.
- **Batch API.** A once-a-day job doesn't need instant answers, and batch requests cost half. The server-side refusal fallback isn't available on batches, so refusals would need a manual retry.
- **Prompt caching.** The instructions are repeated on every classify call; caching them helps once they grow past the minimum cacheable length.
